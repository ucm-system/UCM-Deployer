# UCM Deployer v{VERSION}

**UCM (Unified Cache Management) 安装、环境预检与服务部署工具 —— Windows 桌面版**

面向 vLLM / vLLM-Ascend / SGLang 运行环境（Ascend NPU / NVIDIA GPU），提供五个向导步骤（另含面向多台服务器的可选批量部署）：

```
① 服务器管理 → ② 镜像准备 → ③ 容器准备 → ④ 环境预检 → ⑤ 服务部署（可选：批量部署）
```

## 本版本更新

- **UCM 配置文件写入前移：步骤3 新增「UCM 文件配置」模块 + 批量部署新增「UCM文件配置」页签**：步骤3 创建容器时可一键把可编辑的 UCM 配置写入目标容器（SFTP → `docker exec mkdir` → `docker cp` → 校验，与批量部署共用同一函数）；批量部署「创建容器」阶段开关升级为「创建容器并配置UCM文件」——勾选 = 执行时创建容器（「容器配置」页签）并在每台容器创建完成后写入配置（内容/路径全目标统一，随部署模板导出/导入），未勾选时容器配置与 UCM文件配置两页签均不可选中，写入失败算该台部署失败。
- **步骤5 精简为两模块**：移除重复的配置编辑区——① 拉起命令指引（`UCM_CONFIG_FILE` 高亮随步骤3 写入路径联动）；② 验证连通性（IP/端口/模型名自动生成 + SSH 自动测试）；唯一执行入口为连通性测试。
- **宿主机环境检测扩展**：新增共享内存（shm）与 AIO 设备检查项（容器内预检同口径，不足时 WARN 并提示调整方式）。
- **批量部署挂载表新增「🔎 批量校验」**：对全部勾选目标并行检查每个挂载宿主机路径是否存在（`test -d`），逐项结果与缺失目录的 `mkdir -p` 建议写入各服务器日志页签——分发/创建前先校验，避免挂载失败。

- **步骤1 页面布局调整为 4:3:3 三段分栏**：服务器列表 / 任务记录（检测结果）/ 日志页签比例约 4:3:3（可拖动调整）——列表不再挤占检测结果与日志的高度。
- **步骤3 更名为「UCM容器环境准备」**。
- **步骤5 验证连通性新增「服务器 IP」输入框**（位于端口之前）：验证命令与自动连通性测试按输入的 IP/端口/模型名实时生成，留空默认 127.0.0.1（服务器本机执行）。

- **向导步骤重命名与重排**：① 服务器管理 → ② UCM镜像准备 → ③ UCM容器环境准备 → ④ UCM容器环境预检 → ⑤ 推理服务拉起；**批量部署移至步骤4 与步骤5 之间**（多机场景与单机流程衔接更自然）。
- **步骤5 从纯指引页升级为「编辑配置 + 指引 + 自动验证」**：UCM 配置文件**可直接编辑**，填写目标容器与容器内路径后点「💾 写入容器」自动保存（SFTP 上传 → `docker exec mkdir` → `docker cp` → 校验文件开头），路径修改**自动同步**拉起命令的 `UCM_CONFIG_FILE`；新增「⚡ 执行连通性测试」——通过 SSH 在目标服务器自动执行 `/health`、`/v1/models`、`/v1/chat/completions`（完整对话载荷）并逐项判定，失败给出排查提示。
- **步骤1 环境检测增强与批量操作**：「探测设备」升级为「环境检测」——新增 CANN 版本（≥ 8.0，容器方式部署宿主机无 CANN 自动跳过）、内存（≥ 32GB）、Docker 版本（≥ 20.10，缺失报 FAIL）检测项；新增**「🧪 批量测试连接」与「🔍 批量环境检测」**（列表全部服务器并行执行、每台独立日志页签）；服务器列表新增**「检测结果」列**（PASS/WARN/FAIL/未检测着色，悬浮看明细）。
- **部署模板导入说明与行为明确**：导入模板时服务器按「主机+端口+用户名」匹配写入服务器管理（已存在则更新，模板密码为空时保留本地密码）并自动勾选为部署目标；模板为纯 JSON 可手工编辑。
- **步骤5 提示新增 PD 分离部署说明**：`--kv-transfer-config` 只需在 Prefill 实例的拉起命令中添加，Decode 实例无需添加；单机 / 多机部署按模板原方式使用。
- **界面细节优化**：批量部署目标服务器表与步骤1 服务器列表列宽改为平均分配（可手动拖动调整）；批量执行主按钮靠右、左侧显示执行摘要。

- **仅创建容器/预检（不分发镜像）时镜像名可正常填写**：取消「分发镜像」阶段不再锁定整个「镜像与分发」页签——只禁用分发参数区（分发方式/源服务器/目标保存路径），镜像名始终可编辑，并提示「镜像须已存在于各目标服务器」；分发参数仅在勾选分发时校验。
- **镜像导出改用 `docker save -o`（未压缩 tar），导出速度大幅提升**：镜像层本身已是压缩格式，原 `docker save | gzip -1` 的二次压缩收益极低却大量消耗 CPU（实测 2-3 倍耗时）；现由 daemon 直接流式写 tar，镜像包临时文件相应改为 `.tar`。
- **修复服务器直传 scp 报 Broken pipe**：目标服务器 OpenSSH < 8.4 时 askpass 机制要求 `DISPLAY` 环境变量非空——缺失时 ssh 不调用 askpass，scp 等待密码直到源端 `LoginGraceTime` 超时断连；现自动补充 `DISPLAY`，直传密码认证在无 sshpass、旧版 OpenSSH 环境下正常工作。
- **服务器直传密码认证兜底（无需安装 sshpass）**：目标服务器未装 sshpass 时自动改用 OpenSSH 自带的 `SSH_ASKPASS` 机制代输密码——密码写入 700 权限临时脚本、传输后立即删除；OpenSSH >= 8.4 直接支持，更旧版本借助 `setsid`（均缺失时才提示安装 sshpass 或改用镜像包中转）。
- **批量部署页布局与交互重排**：镜像来源并入部署配置（三页签「镜像与分发 / 容器配置 / 预检配置」），三个**执行阶段开关**（分发镜像 / 创建容器 / 环境预检）移至页签栏右上角——取消勾选即跳过该阶段，对应页签置灰；「同名容器先删除再创建」移入容器配置页签；批量执行区只保留主按钮并实时显示执行摘要（勾选阶段 × 目标台数）。
- **目标服务器勾选交互增强**：点击行任意位置即可勾选（勾选行整行高亮），点「部署」列表头=全选/清空，右键菜单（全选 / 清空 / 刷新列表）替代顶部按钮行。
- **分发前总是自动跳过同名镜像**：移除「目标已存在同名镜像时跳过分发」开关——分发目标就是让镜像就位，已存在即视为成功并跳过（旧部署模板中的 skip_existing 键导入时自动忽略）。
- **配置联动细化**：勾选「自定义 docker run 命令」后附加参数区置灰（不再参与执行）；未勾选「使用自定义预检配置」时预检编辑框置灰（内容保留作参考模板）。
- **批量部署新增「服务器直传」镜像分发方式**：源服务器 `docker save | gzip` 导出后，各目标通过服务器间 scp 拉取镜像包并 `docker load`——镜像**不经本机**、不占本机磁盘与带宽；密码认证经 sshpass（目标未安装时明确提示），日志不回显源服务器密码；全部目标结束后自动清理源端与目标端临时镜像包。
- **目标服务器镜像包保存路径可配置**：tar / 直传模式下镜像包上传到各目标后的保存目录可自定义（默认 `/tmp`，大镜像包可指定如 `/data` 避免空间不足；须为绝对路径），`docker load` 校验完成后自动删除临时包。
- **批量部署预检带宽检查与 KV Cache 挂载联动**：「执行存储带宽检查」依赖容器配置页签的 KV Cache 挂载目录——未添加时禁用并提示「请先添加 KV Cache 目录」；预检挂载目录自动带出第一个 KV Cache 路径（手动编辑后停止带出）；添加/删除/修改 KV Cache 行实时联动开关与提示。
- **步骤5 布局与体验优化**：UCM 配置模板按内容自适应高度（不再下方留白）；模型名输入框默认 `qwen3.8` 且固定宽度；窗口富余高度让给内容更多的拉起命令与验证命令区。
- **向导导航精简**：首步不再显示「上一步」、末步不再显示「下一步」按钮。
- **步骤3 同名容器自动检测（回退「先删除再创建」选项）**：创建容器前仍自动检测同名容器并明确提示（不会执行到 docker run 才因容器名冲突失败）；「自动删除旧容器」的重建选项从步骤3 移除——自动 `docker rm -f` 存在误删风险，需要重建时可通过「工具 → 清理指定容器」先手动删除。
- **批量部署支持自定义 docker run 命令（同构集群）**：勾选后整条执行你填写的命令（所有目标使用同一条，跳过逐台设备适配）；「🔁 生成命令样例」按当前配置一键生成 Ascend 形态样例；命令中可写 `{image}` 占位符执行时自动替换为所选镜像；异构集群保持不勾选仍走逐台自动适配。
- **批量部署目标服务器表新增「环境」列**：显示步骤1「探测设备」时宿主机环境预检的汇总状态（PASS 绿 / WARN 橙 / FAIL 红 / 未探测灰），悬浮查看驱动、内核、SMMU 各项明细——一眼判断哪些服务器可以放心用于批量部署；编辑或删除服务器后状态自动失效，重新探测更新。
- **修复 /usr/lib64 挂载导致容器启动即退出**：不再把宿主机 `/usr/lib64` 挂进 Ascend 容器（宿主机动态库覆盖容器内库目录会使 bash 等程序加载失败立即退出）；系统挂载只接受候选列表内的路径。
- **docker run 命令粘贴兼容**：多行命令压平支持行尾「`\` + 空白」续行格式（从日志复制的命令常见）；自动去掉 `$ ` 日志前缀。
- **步骤1 探测设备同步预检宿主机环境**：加速器驱动（Ascend HDK > 25.2.0 / NVIDIA 驱动）、内核版本（≥ 5.10）、SMMU——与步骤4 容器内预检同一套判定口径，提前在准备镜像与创建容器前暴露基础环境问题；结果逐项写入任务日志，FAIL 项弹窗提示。
- **镜像包服务器保存路径可配置**：tar 导入默认上传到 `/tmp`，大镜像包（十几 GB 级）可改大容量目录（如 `/data`），路径须为服务器绝对路径；`docker load` 完成后 tar 包保留在该目录可复用。
- **批量部署预检 JSON 预填常用模板**：预检配置编辑框预填 `kernel_min`、`bandwidth` 等常用键，叠加于 ucm-toolkit 出厂默认之上，只需写要覆盖的键。
- **whl 校验警告文案规范化**：基础镜像探测不到条件时统一提示「未能确认基础镜像 xxx，跳过 xxx 校验」，明确表示没有校验条件而非包不匹配。
- **修复任务完成提示连环弹出**：任务全部完成回调先断开再触发，避免模态框期间事件重入导致「构建完成」提示多次弹出。
- **批量部署可随时取消**：点「取消」后远端长任务（`docker save` / `docker load` 等）同步中断（SSH 流式命令支持取消回调），不会在后台继续执行。
- **容器创建后自动确认运行状态**：创建完成轮询确认容器 running（约 5 秒）；容器启动即退出时（入口命令异常等）立即给出明确诊断（状态 + 退出码，提示 `docker logs <容器名>` 定位），不再等到预检阶段才报 "not running"。
- **失败信息分层展示**：汇总弹窗/状态栏简短标注「执行失败（详见该服务器日志页签）」，完整失败原因与失败阶段写入各服务器日志页签；「取消」操作保留原提示不被覆盖。
- **源服务器参与条件收紧**：仅在「镜像包中转 + 需要分发」时参与任务，只创建容器 / 预检时源服务器进度不再长期卡住。
- **容器创建失败不再被误判为成功**：docker run 退出码非零时抛出错误（含 stderr 摘要），批量流水线不会继续执行后续阶段。
- **批量部署页可拖分栏**：上半（目标服务器 + 配置模板）与下半（批量执行 + 任务面板）可拖动调整比例；目标服务器列表至少可见 3 行（不再被任务面板挤压），任务面板进度表 2-8 行滚动、日志页签保底高度。
- **测试**：新增宿主机环境预检、镜像包自定义保存路径、批量部署预检默认模板、回调防重入、服务页高亮与验证命令生成、带宽检查与 KV Cache 挂载联动、服务器直传与目标保存路径、勾选交互与执行摘要等用例，全量 286 项通过。

## Bug 修复与体验优化

- **切换服务器残留状态清理**：步骤2 / 步骤3 切换服务器后自动清理上一台的镜像列表、UCM 校验结果、设备探测与 docker run 命令；新服务器镜像获取失败时清空下拉框——修复残留旧命令导致「创建容器」误按上一台参数执行的隐患。
- **预检失败不再伪装通过**：镜像内未安装 ucm-toolkit 或预检未产出任何检查项时，明确报错并给出排查指引（回步骤2 重装 UCM 组件 / 重建镜像），不再追加宿主机检查项把失败算成全 PASS。
- **Ascend 950（A5）机型 urma_admin 挂载**：宿主机存在 `/usr/bin/urma_admin` 时自动以只读方式挂载。
- **统一挂载表默认空表**：步骤3 与批量部署不再预置空「模型」行，挂载表默认为空（即不挂载任何目录），模板回填逻辑同步修正。
- **镜像扫描进度修复**：扫描正常结束时进度条上报 100%，不再停留在最后一次过程进度。
- **步骤3 布局优化**：容器参数（容器名/共享内存/网络）与生成/检查/创建按钮合并为一行，节省纵向空间。
- **Release 工作流修复**：首次发布（无同 tag Release）不再失败。
- **测试**：新增服务器切换残留清理、扫描进度完成、检查容器状态消息、toolkit 缺失/无检查项报错、urma_admin 只读挂载等用例，全量 244 项通过。

## 主要功能

- **步骤1 服务器管理**：SSH 凭据本地加密保存/复用；自动探测设备型号、卡数与 CPU 架构。
- **步骤2 镜像准备**：支持服务器已有镜像、本地 tar 上传、镜像仓库拉取；自动探测基础镜像运行时并校验 UCM/wrapt/ucm-toolkit wheel 兼容性。
- **步骤3 容器准备**：选择 UCM 镜像自动校验安装情况；按宿主机实际存在的设备节点与系统挂载生成可编辑 `docker run` 命令；统一挂载表（KV Cache / 模型 / 自定义）。
- **步骤4 环境预检**：显式选择容器；检查驱动、内核、共享内存、AIO、存储带宽与 SMMU；UCM 与驱动版本支持多来源补齐；支持 JSON 参数叠加配置。
- **步骤5 服务部署**：UCM 配置参考模板、拉起命令模板（含环境变量与 --kv-transfer-config 接入）与连通性验证指引，一键复制照做即可。
- **（可选）批量部署**：多服务器镜像分发、容器创建与环境预检；部署数据模板导出/导入。
- **工具菜单**：按关键字筛选并清理容器/镜像，删除前展示完整确认列表。

## 使用

双击 `UCM-Deployer.exe` 即可（无需 Python）。产物自检：

```powershell
.\UCM-Deployer.exe --smoke
```

源码运行 / 开发见 [README](https://github.com/ucm-system/UCM-Deployer#readme)。
