# 可选 · 批量部署（多服务器）

单台服务器场景请直接使用步骤 3（容器创建）→ 步骤 4（环境预检）→ 步骤 5（服务部署），无需本功能。

在**一台服务器上制作好镜像**（步骤1-2）后，向**多台目标服务器**批量执行：

```
镜像分发 → 容器创建 → 环境预检
```

每台服务器在执行面板中拥有**独立进度条与独立日志页签**；多台服务器的登录信息、容器创建参数与预检参数支持**数据模板（JSON）导出/导入**，一次填写、多机复用。

## 操作流程

### 1. 选择镜像来源

| 分发方式 | 说明 | 适用 |
|---|---|---|
| **镜像包中转**（默认） | 源服务器 `docker save \| gzip -1` 导出 → 下载到本机 → 各目标并行上传并 `docker load` | 离线集群（目标无法访问镜像仓库） |
| **镜像仓库** | 各目标服务器直接 `docker pull` | 目标可访问仓库（内网 registry / 公有仓库） |

- 进入本页时自动带入步骤2 构建完成的镜像与源服务器；
- 「目标已存在同名镜像时跳过分发」：逐台 `docker image inspect` 检查，已存在则跳过上传/拉取（重复执行/增量补装场景）；
- tar 模式下源服务器作为面板**首行**先准备镜像包，其余目标等待就绪后**并行**分发。

### 2. 勾选目标服务器

从注册表勾选**多台**目标（支持「全选 / 清空 / 刷新」）。源服务器也可以同时作为目标——其镜像分发阶段自动跳过（镜像已在本机），容器创建与预检照常执行。

**「环境」列**显示步骤1「探测设备」时宿主机环境预检的汇总结果，方便判断哪些服务器可以用于批量部署：

| 状态 | 含义 |
|---|---|
| PASS（绿） | 驱动 / 内核 / SMMU 全部通过 |
| WARN（橙） | 有建议关注项（悬浮查看明细） |
| FAIL（红） | 有不满足项，建议先修复再部署 |
| 未探测（灰） | 尚未在步骤1 执行「探测设备」 |

悬浮单元格可查看各项明细（内核版本、驱动版本、SMMU 状态等）；编辑或删除服务器后状态自动失效，重新探测即可更新。

### 3. 填写部署配置模板

对全部目标生效，设备差异自动适配：

| 页签 | 配置 |
|---|---|
| **容器配置** | 容器名 / shm-size / --net / 端口映射（NVIDIA）/ KV Cache 目录 / 模型挂载（只读可选）/ 额外挂载 / 附加 docker 参数 / **自定义 docker run 命令（可选）** |
| **预检配置** | 是否执行带宽检查（容器配置未添加 KV Cache 目录时禁用）/ 容器内挂载目录（默认带出第一个 KV Cache 路径）/ 自定义预检 JSON（写入每个目标容器并以 `--config` 引用） |

!!! tip "自定义 docker run 命令（同构集群）"
    勾选容器配置页签底部的**「自定义 docker run 命令」**后，批量部署将**整条执行你填写的命令**（所有目标使用同一条，跳过逐台设备适配），适合设备完全一致的同构集群：

    - 点**「🔁 生成命令样例」**按当前配置（容器名 / 参数 / 挂载表）生成 Ascend 形态样例，设备段为通用形态（`/dev/davinci0 ... 7`、`--privileged=true`），请按实际集群修改；
    - 命令中的 **`{image}` 占位符**执行时自动替换为所选镜像；
    - 容器名请与上方「容器名」保持一致（同名容器检测与状态确认都按它进行）；命令必须以 `docker run` 开头；
    - 异构集群（各台设备数量不同）请保持**不勾选**，让工具逐台现场适配。

- **自定义预检 JSON** 编辑框已**预填默认模板**（含 `kernel_min`、`bandwidth.workers` / `threshold_gb` 等常用键），在默认内容上按需增删即可；配置叠加于 ucm-toolkit 出厂默认之上，只需写要覆盖的键，出厂默认全量键值可在步骤4「预检参数配置」中从容器读取参考。

- **Ascend 目标**逐台现场探测实际存在的设备节点（`/dev/davinci*`、`/dev/ummu` 等，存在时自动 `--privileged`）与驱动/工具挂载；
- **NVIDIA 目标**自动使用 `--runtime nvidia --gpus all`；
- 创建容器前自动校验镜像内 UCM 安装（未安装则该服务器失败并说明原因）。

### 4. 开始批量部署

勾选要执行的阶段（可任意组合：仅分发 / 分发+创建 / 全流程），可选「同名容器先删除再创建」（重复执行场景）。点「🚀 开始批量部署」：

- 页面**上下可拖分栏**：上半（目标服务器 + 配置模板）与下半（批量执行 + 任务面板）可拖动调整比例——任务启动后进度表与日志需要更多高度时，把分栏往下拉即可；
- 每台服务器一行进度条：按阶段权重映射（分发 45% / 创建 25% / 预检 30%）；进度表约 2-8 行滚动展示，日志页签至少可见数行；
- 每台服务器一页日志：完整命令与输出，单台失败**不影响其他服务器**继续执行；
- **部署可随时取消**：点「取消」后远端长任务（如 `docker save` / `docker load`）同步中断，不会在后台继续执行；
- 结束后弹出汇总（每台：镜像分发/跳过、容器名、预检判定）；失败的服务器在汇总中简短标注，**完整失败原因与失败阶段见该服务器的日志页签**。

**容器运行状态确认**：容器创建完成后工具会自动确认其处于 running 状态（约 5 秒内轮询）；若容器启动即退出（如入口命令异常），会立即给出明确诊断（容器状态 + 退出码），并提示在服务器上执行 `docker logs <容器名>` 查看退出原因，而不是等到预检阶段才报错。

## 数据模板：导出 / 导入

多台服务器的**登录信息、容器创建参数、预检参数**往往重复填写——保存为部署数据模板后可分享复用：

- **📤 导出部署模板**：当前勾选的目标服务器登录信息 + 镜像来源 + 容器/预检配置 → JSON 文件。登录密码/私钥口令默认**不**导出（确认后可包含，注意明文存储风险）；
- **📥 导入部署模板**：一次填充全部配置；模板中的服务器按 `主机+端口+用户名` 匹配写入本机注册表（已存在则更新，模板密码为空时保留本地密码），并自动勾选为目标；
- 模板是纯 JSON，可手工编辑 / 批量生成后分发，同事在其机器上导入即用。

```json
{
  "kind": "ucm-deployer-batch-template",
  "template_version": 1,
  "image": {
    "mode": "tar", "ref": "ucm-vllm:0.3.6",
    "source_host": "10.0.0.10", "source_port": 22,
    "skip_existing": true, "recreate_container": false
  },
  "container": {
    "name": "ucm-vllm", "shm_size": "512g", "network": "host",
    "ports": ["8000:8000"], "kv_cache_dirs": ["/mnt/kvcache"],
    "model_mount": {"host_path": "/data/models", "container_path": "/models", "readonly": true},
    "extra_mounts": [], "extra_args": ""
  },
  "precheck": {
    "bandwidth_check": true, "mount_path": "/mnt/kvcache",
    "custom_config_enabled": false, "custom_config_json": {}
  },
  "servers": [
    {"name": "node-1", "host": "10.0.0.11", "port": 22, "username": "root",
     "auth_type": "password", "password": "", "remark": ""}
  ]
}
```

!!! tip "常见失败排查"
    批量执行单台失败不影响其他服务器。汇总弹窗简短标注失败，展开该服务器的日志页签可看到完整原因与失败阶段，常见原因：SSH 不通、磁盘空间不足、镜像无 UCM、挂载目录在容器内不存在、**容器名冲突（同名容器已存在且未勾选重建）**、**容器启动即退出（入口异常，可用 `docker logs` 定位）**。
