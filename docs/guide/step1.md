# 步骤1 · 服务器管理

登录要部署的服务器，执行环境检测。**一次只登录一台**（换勾自动切换），后续所有步骤都作用于勾选的服务器。多台服务器的批量测试/检测见下方「批量按钮」。

![步骤1 界面](../screenshots/step1-servers.png)

## 操作流程

### 1. 添加服务器

点「➕ 添加服务器」，填写登录信息：

![添加服务器](../screenshots/dialog-add-server.png)

- 支持**密码**或**私钥**两种认证方式；
- 登录信息保存在 `~/.ucm_deployer/servers.json`（密码 **Fernet 加密**），下次打开程序直接复用——**打开程序即显示历史服务器列表**；
- 新增后自动勾选登录，无需再手动勾选。

### 2. 测试连接

点「🔌 测试连接」验证 SSH 可达（结果见底部任务面板日志）。

### 3. 环境检测

点「🔍 环境检测」自动识别：

- 设备类型与型号（`npu-smi info` / `nvidia-smi`，如 `Ascend 910B3`、`Ascend950PR`）
- **卡数**（步骤2/3 的设备映射依据）
- **CPU 架构**（`uname -m`，步骤2 匹配校验依据）

同时会**检测宿主机环境**（与步骤4 复检同一套判定口径，提前确认基础环境可用）：

- **加速器驱动**：Ascend 读取 `/usr/local/Ascend/driver/version.info` 或 `npu-smi`，HDK 须高于 25.2.0；NVIDIA 读取 `nvidia-smi` 驱动版本（信息项）
- **内核版本**：`uname -r`，须 ≥ 5.10（按 major.minor 比较）
- **SMMU**：宿主机 `dmesg` 中不应出现 `arm-smmu-v3`（已开启建议进 BIOS 关闭）
- **CANN 版本**：读取 `/usr/local/Ascend/ascend_toolkit_install.info`，须 ≥ 8.0（无 CANN 的 NVIDIA 机器自动跳过）
- **内存大小**：`free -g`，须 ≥ 32 GB
- **Docker 版本**：`docker --version`，须 ≥ 20.10（未安装直接 FAIL，容器创建/批量部署的前置依赖）
- **共享内存**：`df -h /dev/shm`，须 ≥ 512 GB（不足直接 FAIL；创建容器时建议配合 `--shm-size` 调整）
- **可用 AIO 资源**：`fs.aio-max-nr - fs.aio-nr`，须 ≥ **卡数 × 4096**（不足给出 WARN 与 `sysctl -w fs.aio-max-nr` 建议；设备探测未取得卡数时跳过）

检查结果逐项写入任务日志（`[PASS]/[WARN]/[FAIL]/[SKIP]`），同时汇总显示在表格**「检测结果」列**（PASS 绿 / WARN 橙 / FAIL 红，悬浮查看各项明细与未通过项建议）；存在 FAIL 项会弹窗提示——**建议先修复环境，再准备镜像与创建容器**。

检测/探测结果持久保存；步骤2 的构建平台、步骤3 的设备映射都会按该设备类型自动适配。

### 4. 批量按钮

- **「🧪 批量测试连接」**：对**注册表全部服务器**（不限于勾选）逐一测试 SSH 连接；
- **「🔍 批量环境检测」**：对全部服务器逐一执行上面的设备探测与环境检测，结果回填「检测结果」列。

### 5. 勾选登录

勾选「登录」列选择本次操作的服务器。

!!! tip "操作对象统一"
    编辑 / 删除 / 测试连接 / 环境检测均作用于**勾选的服务器**（批量按钮作用于全部服务器）；未勾选时弹提示引导。列表支持关键字筛选与悬浮查看完整名称。

## 常见问题

- **连接失败**：检查 IP/端口/密码；`密码` 与 `私钥` 认证方式需与服务器配置一致。
- **探测不到设备**：确认宿主机已装 `npu-smi`（Ascend）或 `nvidia-smi`（NVIDIA）且在 PATH 中。
